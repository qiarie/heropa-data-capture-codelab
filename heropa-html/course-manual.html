Capture and process health data with Kotlin FHIR Data Capture

This guide takes you through the codelab on the Heropa lab, where you write the code in an editor in your browser and the app runs as a web page. You install nothing.

It is built on the published Data Capture codelab, which was written for Android Studio on your own computer. This guide covers the lab only. If you would rather work in Android Studio, follow the published Data Capture codelab instead of this guide.

The codelab text comes from the Kotlin FHIR Data Capture project under codelabs directory and is used under the Apache License 2.0.

1. Before you begin

What you'll build

In this codelab, you're going to build a Kotlin Multiplatform app with the Kotlin FHIR Data Capture library. Your app will use the library to render and process FHIR Questionnaires and responses. The same code runs on Android, iOS, Desktop (JVM) and Web (Wasm and JS).

This lab focuses on the Web (Wasm) version. Wasm is short for WebAssembly, the format that lets the app run inside your browser. Every build on the lab produces that version only, and the other platforms are not built here.

What you'll learn

  • How to integrate Kotlin FHIR Data Capture library into your Kotlin Multiplatform application
  • How to display a Questionnaire
  • How to get answers as a QuestionnaireResponse
  • How to extract FHIR resources from a QuestionnaireResponse
  • How to add validation and skip logic to a Questionnaire
  • How to design a question in a form builder and add it to a Questionnaire

What you'll need

On the lab you need only a recent version of Chrome, Edge, Brave, Firefox or Safari. The app uses WebAssembly features that older browsers lack.

You do not need to know Kotlin. Every change is given in full, and this guide says exactly which file to open and where to put each line.

This codelab is focused on Kotlin FHIR Data Capture. Non-relevant concepts and code blocks are glossed over and are provided for you to simply copy and paste. If you haven't built a Kotlin Multiplatform app before, you can start by creating your first Compose Multiplatform app.

What an import is

Code refers to things by short names, such as Questionnaire. An import line says which library a short name comes from. If the import is missing, the build fails with Unresolved reference.

Where import lines go

All import lines sit together near the top of App.kt, each starting with the word import. In the starter code they run from line 18 to line 50. Right under them, the lab has put one numbered comment for each step that needs imports.

import org.jetbrains.compose.resources.stringResource

// 4 Imports for the Questionnaire composable

// 5 Import for the JSON encoder

// 6 Imports for extracting FHIR resources

Each step tells you which of these comments to paste its imports under. You never have to hunt for the right spot. The order of import lines does not matter.

One name, two meanings

Two different things in this codelab are both called Questionnaire.

Import line What it is Used in

import dev.ohs.fhir.model.r4.Questionnaire as FhirQuestionnaire The FHIR data behind the form, given a second name so the two do not clash Step 6

If App.kt imports dev.ohs.fhir.model.r4.Questionnaire without the as FhirQuestionnaire ending, the build fails with No parameter with name 'questionnaireJson' found. Delete that line and use the two lines above.

Open shared/src/commonMain/kotlin/dev/ohs/fhir/codelab/App.kt. The App() composable already reads the questionnaire JSON from the resources into questionnaireJson, and creates a coroutine scope that you'll use later in this step:

The Questionnaire composable requires a JSON encoded FHIR Questionnaire for it to render.

You can look at the questionnaire.json file if you want, but one of the benefits of Kotlin FHIR Data Capture is that you don't need to know the structure of the FHIR Questionnaire (or anything about FHIR) to get it to render it! You'll look more closely at this file later in the codelab.

The three steps below make this change. These notes tell you where each thing they name is.

  • The comment // 4 Replace with code from the codelab to display the questionnaire. is inside App(), near line 83 now that the imports are in. Press Ctrl+F and type // 4 Replace to jump to it. Just under it is the line that starts with Text(text = "Hello World!".
  • Select both of those lines, delete them and paste the block from step 3 where they were. The new block starts with its own numbered comment, // 4 Display the questionnaire.

  1. Find the // 4 Replace with code from the codelab to display the questionnaire. comment in App().

Step 2: Handle the Submit button

At the moment nothing happens when you tap Submit. The library calls onSubmit when the button is tapped, so replace onSubmit = {}, with the following code:

  1. Find the line onSubmit = {},. It is inside the block you pasted in Step 1, five lines under the // 4 Display the questionnaire comment. Press Ctrl+F and type onSubmit to jump to it. This piece of code does not have its own numbered comment.

  2. Replace that one line with these five lines. Leave the onCancel = {}, line under it in place.

    onSubmit = { getQuestionnaireResponse ->
  // getQuestionnaireResponse() validates the answers first. If validation fails, the
  // library shows an error dialog and cancels this coroutine.
  scope.launch { submitQuestionnaire(questionnaireJson, getQuestionnaireResponse()) }
},

The new code uses launch, which is why you added the kotlinx.coroutines.launch import at the start of this step.

getQuestionnaireResponse is a suspend function, so it is called from a coroutine launched in scope. It validates the answers before it returns the response. If any answers are invalid, the library shows a dialog that lists them and cancels the coroutine, so you don't have to handle validation errors yourself.

The response is passed on to submitQuestionnaire(), at the end of App.kt, which is still empty. You'll fill it in over the next two steps.

Your App() composable should now look like this:

@Composable
fun App() {
  val darkTheme = isSystemInDarkTheme()
  MaterialTheme(colorScheme = if (darkTheme) darkColorScheme() else lightColorScheme()) {
    Scaffold(topBar = { AppBar(darkTheme) }) { innerPadding ->
      Box(
        modifier = Modifier.fillMaxSize().padding(innerPadding).consumeWindowInsets(innerPadding)
      ) {
        var questionnaireJson by remember { mutableStateOf<String?>(null) }
        LaunchedEffect(Unit) {
          questionnaireJson = Res.readBytes("files/questionnaire.json").decodeToString()
        }
        val scope = rememberCoroutineScope()

        // 4 Display the questionnaire
        questionnaireJson?.let { questionnaireJson ->
          Questionnaire(
            questionnaireJson = questionnaireJson,
            config = QuestionnaireConfig(showCancelButton = false),
            onSubmit = { getQuestionnaireResponse ->
              // getQuestionnaireResponse() validates the answers first. If validation fails, the
              // library shows an error dialog and cancels this coroutine.
              scope.launch { submitQuestionnaire(questionnaireJson, getQuestionnaireResponse()) }
            },
            onCancel = {},
          )
        }
      }
    }
  }
}

Save App.kt and wait for BUILD OK. The form looks the same as before. Clicking Submit still shows nothing, because submitQuestionnaire() is empty until the next step.

6. Extract FHIR Resources from a QuestionnaireResponse

The questionnaire included with the starter project is for a simple patient registration flow, so you may ultimately want to use the questionnaire responses to create a FHIR Patient resource based on them. This conversion from a questionnaire response to FHIR resources is called data extraction. We can do this with the TemplateExtractionEngine class of Kotlin FHIR Data Capture.

To perform data extraction, your questionnaire must be authored to include information on how to perform the data extraction. Luckily, the sample questionnaire is already set up for Template-based extraction. If you open questionnaire.json, you'll find:

  • A Patient resource with the ID patient-template in the contained array. This is the template for the resource that gets extracted.

  • An sdc-questionnaire-templateExtract extension on the questionnaire, which points to the template with #patient-template.

  • An sdc-questionnaire-templateExtractValue extension on each template field that comes from an answer. It holds a FHIRPath expression that picks the answer, for example the family name:

    %resource.repeat(item).where(linkId='PR-name-family').answer.value.first()

  • Template fields without an extension, such as the identifier system, which are copied to the extracted resource as they are.

The questionnaire also has definition elements and an sdc-questionnaire-itemExtractionContext extension. These are for Definition-based extraction, which the library doesn't support, so they are ignored.

To see questionnaire.json, click its tab, the third one in the Code area. If you closed it, go to the Explorer and open shared, then src, then commonMain, then composeResources, then files, and click the file. You only read it in this step. Do not change it.

This step needs two imports. In App.kt, find the // 6 Imports for extracting FHIR resources comment, which sits under the import you added in step 5. You can also press Ctrl+F and type // 6 Imports. Replace that comment with the following code.

// 6 Imports for extracting FHIR resources

import dev.ohs.fhir.model.r4.Questionnaire as FhirQuestionnaire

The // 6 Imports comment is not in the published codelab. The lab adds it to the starter code to mark the place.

Copy the last line in full, with its as FhirQuestionnaire ending. Without that ending the build fails, because the name Questionnaire would then mean two different things.

Find the submitQuestionnaire() method and replace the // 6 Replace with code from the codelab to extract FHIR resources from the questionnaire response. comment with the following code:

  1. Go to submitQuestionnaire(), at the very bottom of App.kt. Press Ctrl+F and type // 6 Replace to jump to the comment. It sits under the // 5.2 Print the questionnaire response lines you added in step 5.

  2. Select that one comment line and paste these four lines over it.

    // 6 Extract FHIR resources from the questionnaire response

val bundle = TemplateExtractionEngine.extract(questionnaire, questionnaireResponse)
println("extraction result: ${json.encodeToString(bundle)}")

TemplateExtractionEngine.extract() requires a Kotlin FHIR Questionnaire, which you can create by decoding the questionnaire JSON string from earlier, and a QuestionnaireResponse, which we already got earlier. It returns a transaction Bundle containing one or more extracted resources–in this case a single Patient resource.

Your submitQuestionnaire() method should now look like this:

private fun submitQuestionnaire(
  questionnaireJson: String,
  questionnaireResponse: QuestionnaireResponse,
) {
  // 5.2 Print the questionnaire response
  println("response: ${json.encodeToString(questionnaireResponse)}")

  // 6 Extract FHIR resources from the questionnaire response
  val questionnaire = json.decodeFromString<FhirQuestionnaire>(questionnaireJson)
  val bundle = TemplateExtractionEngine.extract(questionnaire, questionnaireResponse)
  println("extraction result: ${json.encodeToString(bundle)}")
}

7. Add validation and skip logic to the questionnaire

So far the form accepts whatever you type, and it always shows the same questions. In this step you change both, without touching the Kotlin code. Everything you add goes into questionnaire.json. The library reads the file and does the rest.

This is the main idea behind a FHIR Questionnaire. The rules of a form live in the form's own definition, so the same file behaves the same way in every app that shows it.

You add four rules by hand. At the end of the step you add one more question with a form builder, a tool that writes the JSON for you.

Rule Where it goes What it does in the app
A required answer First Name and Family Name The form reports an error when a name is empty
A lowest allowed value Date of Birth A date before the year 1900 is refused
Skip logic A new yes or no question, and a new Phone number question Phone number is shown only after you answer Yes
A pattern the answer must match Phone number Anything other than ten digits is refused

In FHIR the first rule is the required element and the third is the enableWhen element. The second and the fourth are extensions, named minValue and regex.

Go to questionnaire.json the same way as in step 6, by its tab in the Code area. If you closed it, go to the Explorer, open shared, then src, then commonMain, then composeResources, then files, and click the file. Press Ctrl+F to find each line the steps name.

Keep every comma. JSON separates the parts of a list with commas, and one missing or extra comma breaks the whole file. Each block below already has the commas it needs, so paste it as it is. How far a line is indented does not matter.

Make the two names required

  1. Find the line "linkId": "PR-name-given",. It belongs to the First Name question.

  2. Click at the end of that line, press Enter and paste this line.

    "required": true,

  3. Find the line "linkId": "PR-name-family", and paste the same line under it.

Set the earliest date of birth

  1. Find the line "linkId": "PR-birthdate",.

  2. Click at the end of that line, press Enter and paste this block.

    "extension": [
  {
    "url": "http://hl7.org/fhir/StructureDefinition/minValue",
    "valueDate": "1900-01-01"
  }
],

Add a question that is shown only when it is needed

  1. Find the line "text": "Date of Birth". The line under it holds only }, and closes the Date of Birth question.

  2. Click at the end of that }, line, press Enter and paste this block. It adds two questions.

    {
  "linkId": "PR-has-phone",
  "type": "boolean",
  "text": "Does the patient have a phone number?"
},
{
  "linkId": "PR-phone",
  "type": "string",
  "text": "Phone number",
  "required": true,
  "enableWhen": [
    {
      "question": "PR-has-phone",
      "operator": "=",
      "answerBoolean": true
    }
  ],
  "extension": [
    {
      "url": "http://hl7.org/fhir/StructureDefinition/regex",
      "valueString": "^[0-9]{10}$"
    }
  ]
},

The first question is a yes or no question. The second one carries the skip logic in enableWhen, which names the question to watch, PR-has-phone, and the answer that switches it on, true. The pattern ^[0-9]{10}$ means exactly ten digits. Phone number is required as well, and that rule applies only while the question is shown.
